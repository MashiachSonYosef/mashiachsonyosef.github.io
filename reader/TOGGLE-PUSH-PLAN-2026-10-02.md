written 2026-10-02 for a later session that has R2 credentials, this directory, and the instruction "run the suite"; revised the same day on three adversarial reviews. it is built only on what five read-only reports of this date cite and on lines opened in this tree the same day; where the tree does not say, the line says so and the question is listed in section 9. nothing here chooses: the driver proposes and prints, the owner rules. nothing here types a number a record can say — no commit hash, no manifest count, no zone count: where one is needed the line gives the command that reads it on the day.

the three files of the suite, all under `reader/`:

- `tools/push-toggles-v1.mjs` — the driver, rule `toggle-push-rule-v1-the-driver-proposes-and-prints-and-never-chooses`: the plan, the inventory, the fetch. it also carries the queue's rule id as a constant and faults the queue when the two differ, so the manifest (which reads `tools/` and never `data/`) sees both

every command below is run from `reader/`, the directory this file is in. `<slug>` is a book's slug as `data/zones/<slug>.bin` spells it; `<stamp>` is the day's date, YYYY-MM-DD, given on every command and never read off the clock. the report is `build/toggle-push-report-<stamp>.md`, written by the operator as the steps run and never by the driver (section 6).

## 1 · what a toggle is here

a toggle is a ledger of Moses's, counted on R2, projected over a zone's own positions by a tool of this lane, re-glossed so the line can answer under the new keys, re-pinned on the shelf, drawn as a row of the rail, and ruled on by the owner — the six steps of `tools/TOGGLE-PIPELINE-v1.md` (the table at lines 9-16: 1 count, 2 project, 3 regloss, 4 shelf, 5 rail, 6 ruling).
the join is verse by verse, in order, proved by `form_key == k` at every position, or the whole verse is held and counted on the receipt, never patched around (lines 20-30).
a row whose layer is not on the zone is drawn dead with what it waits on, never dropped (line 15); a zone that changes without a new pin is refused by the reader, by design (line 14).
the ruling is recorded on the projection's receipt, at `emitted_from.toggles.<name>.rulings_owed`, and only then does the row go live (line 16); until then the suite stops in front of the owner.

## 3 · the inventory

    node tools/push-toggles-v1.mjs --inventory

what it does FIRST: the ledger of ledgers. the owner says Moses keeps an index of every ledger delivered, which the owner calls "the ledger of ledgers". nothing in this tree has read it, so the driver tries the plain names the queue types under `r2.ledger_of_ledgers` — `ledger-of-ledgers`, `LEDGER-OF-LEDGERS`, `ledger_of_ledgers`, with `.md` `.json` `.jsonl` `.csv` `.txt` — matched case-insensitively against the objects that sit directly under the ledgers root (`moses-ledgers/`). found: it is fetched to `build/ledgers/<its name as listed>`, held to its listed size, and printed whole before the listing — read it before anything else in this section; the listing below is what the driver falls back to. absent: one line says so and the listing follows. with `--prefix <p>` the ledgers root is still listed first for this one purpose.

then the listing: a signed `GET /<bucket>/?list-type=2&prefix=<prefix>` — ListObjectsV2, paged by continuation token — signed exactly as the GET in `tools/restore-shelf-from-history-v1.mjs:92-109`: SigV4, region `auto`, service `s3`, path-style, `x-amz-content-sha256: UNSIGNED-PAYLOAD`, with a canonical query string added. no tool in the tree listed a prefix before this, and the tree references no R2 command line (no `aws`, `rclone` or `wrangler` anywhere), so the list call is the driver's own and is the minimal one. it lists `moses-ledgers/` (`r2.ledgers_root` in the queue, or `--prefix <p>`) and every queue prefix not under it (today: `moses-parse-source-and-declaration-v1/declaration-store-v7/`).

what it prints, per delivery folder: object count, size, and a verdict, tested in this order — the roots first (an object sitting at `moses-ledgers/` or at `moses-ledgers/toggle-builds-v1/`, where `README-v1.md` sits, is "the root itself", never the property of an entry beneath it); then the queue entries, which claim a folder only when the folder IS the entry's prefix or sits under it (`folder === prefix || folder.startsWith(prefix)`, never the reverse), with their status; then "not a toggle" for the prefixes the queue lists under `known_prefixes_that_are_not_toggles` (the reseal streams, the frame); then UNKNOWN, with the folder's object names printed so a queue entry can be typed for it. an unknown folder under `moses-ledgers/toggle-builds-v1/` is a toggle Moses counted that this lane has not projected: section 4.7, and the driver names the template entry from the queue (`is_template`), not from a literal. it also says whether `moses-ledgers/toggle-builds-v1/README-v1.md` is there (one row per toggle with the ruling it still needs, `tools/TOGGLE-PIPELINE-v1.md:11`), which known prefixes hold nothing, and — for the entries whose prefix is `unknown` (the witnessed order, the joined runs, the piece gloss) and for `qere-ketiv-v1.json` — where in the listing their file names turn up, if anywhere. its last line, when a folder is unknown: add it to the queue, typed in the open, BEFORE fetching it — the order section 4.7 keeps.

what a delivery folder looks like, as the sources describe the ones that have landed:

- a per-position ledger: one gzipped CSV with a header row, one row per position — `book, ref, i, j, surface, form_key, ...` (`tools/TOGGLE-PIPELINE-v1.md:11`); the headword's is `word-lemma-v1.csv.gz`, split on bare commas (`tools/project-toggle-headword-v1.mjs:72-83`)
- the lattice: three files per book, `positions-<slug>-v12.jsonl.gz`, `routes-<slug>-v12.jsonl.gz`, and the lane's receipt `lattice-<slug>-v12.json` carrying both files' sha256 (`tools/project-lattice-v12-v1.mjs:100-113`)
- V: three count tables, the reverse index, `SHA256SUMS.txt`, `V-SERVING-CONTRACT-v2.md`, `v-ledger-v2.json`; the object count is on `data/v-ledger-posture-v1.json` under `delivery.objects`, which the driver prints
- the declarations: a `fix/` directory with `MANIFEST-declarations-v6.json` pinning every file of the delivery, among them the contract, the vocabulary and three jsonl files the projector opens by name (`tools/project-declarations-v1.mjs:104-108`, `:238-245`); the delivery is the full manifest-pinned set, and the pinned count is on `data/source-declarations-receipt-v1.json` under `ledger_pins`

how a delivery is verified:

1. `node tools/push-toggles-v1.mjs --fetch <id>` downloads into `build/ledgers/<id>.incoming/` (a stale incoming directory is removed first), writing each object only when its length is the listing's `Size` (as the restore writes a bin only when it is its pin), then looks for `SHA256SUMS` or `SHA256SUMS.txt` at the delivery's root and holds every listed file to it — `sha256sum -c` done in node, the form `data/v-ledger-posture-v1.json` records under `delivery.integrity` for V. a mismatch, a listed file that is missing, or an object that did not arrive at its listed size is REFUSED with exit 1, and the incoming directory is deleted whole: nothing lands at `build/ledgers/<id>/`, and a delivery already standing there from an earlier verified fetch is left as it was. only a delivery that holds to its sums is renamed into place.
2. a delivery with no sums file is held to the listing's sizes, renamed into place, and printed UNVERIFIED by a sums file with every object's sha256 measured; the verification is then the projector's own pin: the lattice projector refuses `LATTICE_SHA_MISMATCH` against its receipt (`tools/project-lattice-v12-v1.mjs:109-113`); the declarations projector re-hashes every pinned file against its manifest (`LEDGER_PIN_FAILED`, `LEDGER_BYTES`, `:121-122`); the headword ledger's measured sha256 and byte count must equal `emitted_from.toggles.headword.source.sha256` and `source.bytes` on a zone that carries it, which the driver prints in plan mode (read off the zone, never typed). `source.path` is the local file name the projector was given and is not a pin (section 5).
3. the staging directory is `build/ledgers/<id>/`; `build/` is gitignored scratch (the tree's `.gitignore`, lines 3-8) and nothing of a delivery is copied into `data/`. `--fetch <id> --dry` lists what would land and writes nothing. a single object named outright (`--fetch moses-ledgers/toggle-builds-v1/README-v1.md`) lands under its parent folder's name, `build/ledgers/toggle-builds-v1/README-v1.md`.
4. the driver refuses `--fetch` for an entry whose status is proposed or whose objects list is empty, printing the entry's stop line and, where another entry shares the prefix, naming it: `ben-yehuda` (proposed, withdrawn), `strict-pointing` (the lattice's own delivery: fetch `lattice-v12`), `v-word-layer` (the anchors ride in the V delivery: fetch `v-counts`), and the template entry. a bare prefix that is an entry's prefix is held to the same rule, so `--fetch moses-ledgers/ben-yehuda-v1/` is refused too.

## 8 · what must never be done

- never patch a join by hand. a verse that does not prove is held whole and counted on the receipt (`tools/TOGGLE-PIPELINE-v1.md:20-30`); a held verse is a finding, not a fault, and it goes into the report as the receipt says it.

- never describe `tools/emit-zone-store-v1.mjs` as pin-preserving: it pins the directory as it stands.
- never touch the Hebrew. "no masoretic markings can be removed from the book page" (the note above `MASORAH_KEY` in `zone.html`); a projection writes beside the word, never in it, and the browser checks hold the section's bytes identical across positions.
- never choose a default. every row's default is the owner's ruling (`tools/TOGGLE-PIPELINE-v1.md:124-125`); the driver prints positions and picks none.
