## When Spark Spend Is Justified

Spark spend is justified when all are true:

1. Inputs are named.
2. Command, schema, key, count definition, or expected output class is supplied.
3. Output is mechanical and consumable by Agent 1-4/10/5/7/8.
4. Stop condition is artifact produced or `missing_pipeline_blocker`.
5. No source/license/QA/Definition/runtime/publication/product/answer acceptance is requested from Spark.

## One-Line `no_queued_item` Rule

`no_queued_item` is valid only when the Spark just returned an artifact or blocker and Agent 5/7 have checked the standing queue for the next exact item; otherwise reseed one named mechanical task or record the exact missing input/schema/command that prevents reseeding.
