# Oracle 9 Low-Intelligence Agent 1-4 Operating Rule - 2026-06-04

## Owner Decision

Agents 1-4 may run at lower intelligence. This is workable if their tasks become narrower, more deterministic, and more template-driven.

## Rule

Low-mode Agents 1-4 should not carry broad ambiguity. They should execute one pipeline-building step at a time with exact inputs, output shape, validator, and blocker language.

## What Changes

| Lane | Low-mode shape |
|---|---|
| Agent 1 | Build one source/license/custody pipeline contract or script at a time from named source-family targets |
| Agent 2 | Build one definition/lemma/reader-hint candidate pipeline or unmatched-count workset at a time |
| Agent 3 | Build one linkage/dedupe/navigation matrix pipeline at a time from named route/candidate inputs |
| Agent 4 | Build/run one validator/prereq harness for a changed package or named baseline target |

## What They Should Not Do In Low Mode

- Choose broad strategy.
- Resolve license doctrine.
- Decide Definition authority.
- Decide release/package readiness.
- Interpret public reception risk.
- Write long governance/status reports.
- Invent new schema or route authority from memory.

## Required Task Template For Low-Mode Agents

Every task to Agents 1-4 should include:

`target | files | exact command/script to write or run | output artifact | schema/counts | validator | missing-field blocker | handoff owner | stop condition`

## Good Low-Mode Output

Good output is compact and executable:

- script created;
- validator created or missing-validator blocker named;
- rows/counts produced;
- matrix produced;
- exact blocker named;
- Spark-1 can continue from the artifact.

## Bad Low-Mode Output

Bad output is:

- strategic essay;
- vague blocker;
- broad discovery;
- status without artifact;
- acceptance claim;
- route/license/Definition decision.

## Non-Acceptance Boundary

This is operating guidance only. It creates no QA acceptance, source/provenance acceptance, license acceptance, Definition authority, runtime acceptance, publication readiness, product/data acceptance, answer acceptance, accepted gloss, or accepted text.
