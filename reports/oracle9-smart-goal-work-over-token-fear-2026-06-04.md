# Oracle 9 Smart Goal Work Over Token Fear - 2026-06-04

## Owner Rule

Work is work. The project is not afraid of token burn when tokens are producing useful pipeline/data/product progress.

The project is afraid of low-value churn, fake motion, vague reports, passive waiting, and bad authority claims.

## Good Token Burn

Token use is good when it produces:

- runnable scripts;
- pipeline contracts;
- candidate rows;
- source-family maps;
- definition/lemma/reader-hint matrices;
- linkage/dedupe/navigation matrices;
- validator harnesses;
- exact blockers;
- Agent 6-ready boundary questions;
- release/package intake matrices.

## Bad Token Burn

Token use is bad when it produces:

- repeated status reports;
- governance essays with no target/action;
- proof maps that do not change work;
- repeated unchanged validators;
- idle/wake loops;
- vague "blocked" claims without exact missing fields;
- acceptance claims outside authority.
